## 📋 Epic Summary

Fix the **fabricated quotation ID display** in the builder Step 3 and verify consistent QT code display across all surfaces. Currently, the builder creates a fake QT code by slicing the Convex document `_id` hash (producing codes like `QT-81XDBF`), while the actual stored code is sequential (`QT-000003`).

### Root Cause Analysis

**File**: `src/components/modules/admin/quotations/builder/steps/step3-review-send/index.tsx`, line 135-136

```typescript
const code = quotationId
  ? `QT-${quotationId.slice(-6).toUpperCase()}` // ← BUG: takes last 6 chars of Convex _id
  : "DRAFT";
```

The Convex document `_id` is a hash like `j57d3xdbf82k`, so `slice(-6)` produces `f82k0x` → `QT-F82K0X`. The _real_ code generated by `generateQuotationCode()` on the backend is `QT-000003` (sequential, 6-digit padded).

### Target State

- Builder Step 3 shows `quotation.code` from the saved quotation, or `"NEW DRAFT"` if unsaved
- All surfaces consistently display the real sequential QT code
- Send Drawer receives the real code, not the fabricated one

## 📊 Detailed Story Specifications

### Story 25.1: Fix fabricated QT code in builder Step 3

**File**: `src/components/modules/admin/quotations/builder/steps/step3-review-send/index.tsx`

**Current** (line 135-136):

```typescript
const code = quotationId
  ? `QT-${quotationId.slice(-6).toUpperCase()}`
  : "DRAFT";
```

**Fix**: Use the actual quotation code from the saved data:

```typescript
const code = quotation?.code || "NEW DRAFT";
```

Where `quotation` is fetched via the quotation query when `quotationId` exists. The builder context should already expose the saved quotation data.

Additionally, the `SendQuotationDrawer` (or new `FinalizeQuotationDrawer`) passthrough on line 483 should use the real code:

```typescript
code: quotation?.code || "DRAFT",  // instead of reviewQuotation.code
```

**Acceptance Criteria**:

- [ ] Builder Step 3 header shows `quotation.code` (e.g., "QT-000003") when quotation is saved
- [ ] Builder Step 3 header shows "NEW DRAFT" when quotation is not yet saved
- [ ] Send/Finalize drawer shows the real QT code, not the fabricated hash
- [ ] No references to `quotationId.slice(-6)` remain in the codebase
