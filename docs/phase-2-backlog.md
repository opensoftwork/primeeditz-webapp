# Phase 2 Backlog: Advanced File Upload System

This document tracks high-priority features offloaded from Phase 1 to ensure a stable MVP release while preserving the vision for a robust, industrial-grade asset management system.

## 📋 Objective

Upgrade the Project Wizard's file upload mechanism from a standard "blind" upload to a granular, persistent, and resumeable multipart system.

## 🚀 Key Features

### 1. Granular Progress Visualization

- **Status:** Phase 2
- **Description:** Replace the global spinner with per-file progress meters.
- **Requirement:** Users should see exactly what percentage of a specific file (e.g., `ceremony_4k.mp4`) has been transmitted.
- **UX Goal:** Build trust through transparency and real-time feedback.

### 2. S3 Multipart Persistence (Pause/Resume)

- **Status:** Phase 2
- **Description:** Implement S3 Multipart Upload APIs (MinIO natively supports this).
- **Requirement:** If an upload fails due to network instability or the user pauses it, the system should remember which chunks (e.g., 5MB parts) have already been received.
- **Mechanism:** Store `UploadId` and `CompletedParts` in the Project Draft in Convex.

### 3. Cross-Device Context Awareness

- **Status:** Phase 2
- **Description:** Detect partial uploads across different devices.
- **Requirement:**
  - Use "Fingerprinting" (File Name + Size + Last Modified) to identify files.
  - If a user moves to a new device, show a "Partial Found" status.
  - **Logic:** Since browsers cannot access local files without permission, prompt the user: _"We have 40% of this file. Please re-select 'video_final.mp4' to resume transmission."_

### 4. Resilient Conflict Resolution

- **Status:** Phase 2
- **Description:** Handle edge cases where a file with the same name might be a different version.
- **Requirement:** Validate fingerprints before resuming to ensure we aren't stitching different file versions together.
